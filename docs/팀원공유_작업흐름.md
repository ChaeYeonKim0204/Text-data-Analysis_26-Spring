# 팀원 공유용 작업 흐름 정리

## 1. 보고 목적

- 이 문서는 현재 저장소의 분석 작업을 팀원이나 지도교수가 빠르게 파악할 수 있도록 정리한 진행 보고용 문서임
- 초점은 "무슨 데이터를 어떻게 가공했고, 어떤 분석을 했으며, 1차 결과가 무엇인지"를 한 번에 설명하는 데 있음
- 세부 구현 규칙은 별도 문서에서 확인 가능
  - 전처리/토큰화 규칙: `docs/전처리_토큰화_안내.md`
  - 현재 상세 진행상황: `docs/분석_진행상황.md`

## 2. 분석 질문

- 분석 대상
  - 기간: `2026-05-05 ~ 2026-05-11`
  - 매체: 9개 언론사
  - 비교 단위: 4개 매체그룹
    - 경제
    - 통신·보도
    - 정치색
    - 지상파

- 핵심 질문
  - 각 매체그룹은 어떤 의제를 상대적으로 더 크게 다루는가
  - 같은 의제를 다룰 때 어떤 단어 선택과 정서값 차이를 보이는가

## 3-1. GitHub에 올라간 파일과 로컬 전용 파일

- 현재 GitHub에 올라간 것
  - 문서
    - `README.md`
    - `AGENTS.md`
    - `CLAUDE.md`
    - `docs/분석_진행상황.md`
    - `docs/전처리_토큰화_안내.md`
    - `docs/팀원공유_작업흐름.md`
  - 코드/노트북
    - `notebooks/crawling/` 아래 수집, 전처리, 분석 노트북 전반
  - 공용 리소스
    - `resources/knu_sentiment.json`
  - 일부 수집 산출물
    - `data/crawling/` 아래 링크 JSON, 본문 CSV, 체크포인트 JSON, 재실패 JSON, URL 통계 CSV

- 현재 GitHub에 올라가지 않은 것
  - 언론사 분석 입력 데이터 전체
    - `data/news/` 전체
    - 예: `전처리_본문_언론사_260505_260511.csv`
    - 예: `분석토큰_언론사_260505_260511.csv`
  - 분석 결과물 전체
    - `outputs/` 전체
    - 예: `분석코퍼스_언론사_260505_260511.csv`
    - 예: `토픽_대표단어_언론사_260505_260511.csv`
    - 예: `의제비중_절대_260505_260511.csv`
    - 예: `감성요약_언론사_260505_260511.csv`
  - 대용량 통합 수집본 일부
    - `data/crawling/통합_본문_bs4*.csv`

- 이렇게 나눈 이유
  - `data/news/`와 `outputs/`는 생성 산출물 성격이 강함
  - 일부 파일은 용량이 커서 Git 관리에 적합하지 않음
  - 따라서 GitHub에는 재현에 필요한 코드/문서/핵심 리소스를 두고, 대용량 입력과 결과는 로컬에서 관리하는 구조임

- 협업 시 주의점
  - 팀원이 **코드와 방법**만 보려면 GitHub 저장소만 받아도 됨
  - 팀원이 **동일 결과를 바로 확인**해야 하면 아래 로컬 파일을 별도로 공유해야 함
    - `data/news/전처리_본문_언론사_260505_260511.csv`
    - `data/news/분석토큰_언론사_260505_260511.csv`
    - `outputs/` 전체 또는 필요한 핵심 결과 CSV

## 4. 전체 작업 흐름

```text
기사 수집
-> 본문 통합
-> 전처리
-> 토큰화
-> 분석 대상 확정
-> 토픽모델링
-> 매체그룹 비교
-> 감성 분석
-> 워드클라우드
```

- 각 단계는 별도 오케스트레이터 없이 파일 기반으로 연결됨
- 즉, 앞 단계 산출 CSV를 다음 단계 노트북이 읽는 구조임
- 실질적인 분석 파이프라인은 아래 5개 노트북이 담당함
  - `01_필터감사`
  - `02_LDA`
  - `03_매체그룹비교`
  - `04_감성`
  - `05_워드클라우드`

## 4-1. 자주 나오는 용어 설명

- 분석 우주
  - 수집된 기사 전체가 아니라, 전처리와 필터링을 거친 뒤 **실제로 분석에 투입된 최종 기사 집합**을 뜻함
  - 이 프로젝트에서는 날씨 기사, 클로징 기사, 중복 기사, 토큰이 너무 적은 기사, 소프트뉴스를 제외한 뒤 남은 `10,616건`이 분석 우주에 해당함

- 전처리본
  - 원문 기사를 사람이 읽기 쉬운 형태로 정리한 중간 산출물
  - 기자명, 푸터, 방송 태그 등을 제거했지만 기사 본문 구조는 대체로 유지함

- 분석토큰
  - 실제 분석 모델에 넣기 위해 만든 최종 텍스트 입력
  - 형태소 분석과 불용어 제거를 거친 `tokens` 컬럼이 핵심임

- 토픽 비중(theta)
  - 한 기사가 특정 토픽을 얼마나 많이 담고 있는지를 나타내는 비율값
  - 이 프로젝트에서는 기사별 theta를 평균내어 "어떤 매체그룹이 어떤 의제를 더 크게 다뤘는가"를 비교함

## 5. 데이터 가공: 전처리와 토큰화

### 5-1. 전처리 단계

- 사용 노트북
  - `언론사_네이버뉴스_전처리_colab.ipynb`

- 목적
  - 뉴스 기사 본문에서 분석에 불필요한 비본문 요소 제거
  - 원문 보존과 분석용 정제본 생성을 분리

- 실제로 수행한 일
  - 기자명, 이메일, 저작권 문구, 제보 문구 제거
  - 방송 뉴스 태그(`<앵커>`, `[기자]`, `[리포트]`) 제거
  - 기사 하단 제작진 표기, 사진 출처, 푸터 제거
  - `body` 원문은 남기고 `body_cleaned`를 별도 생성
  - `is_weather`, `is_closing`, `is_within_press_dup`, `is_cross_press_dup` 플래그 생성

- 전처리 단계의 의미
  - 사람 기준으로 읽을 수 있는 정리본 생성
  - 이 단계에서는 원문 훼손을 최소화하는 보수적 정제를 지향
  - 즉, 애매한 내용은 남기고 다음 단계에서 걸러내는 방식임

### 5-2. 토큰화 단계

- 사용 노트북
  - `언론사_네이버뉴스_분석토큰화_colab.ipynb`

- 목적
  - 기사 텍스트를 토픽모델링과 빈도 분석에 바로 넣을 수 있는 형태로 변환

- 실제로 수행한 일
  - `title_cleaned + body_cleaned`를 합친 `text` 사용
  - HTML 엔티티 정리, 이모지 제거
  - Kiwi 형태소 분석 수행
  - 명사류 중심 토큰 추출
  - 뉴스 상투어 불용어 제거
  - 핵심 의제어는 사용자 사전/보존어로 유지

- 전처리본과 토큰본의 차이
  - `전처리_본문_언론사_*.csv`
    - 사람이 읽는 용도의 정제본
    - 본문 구조와 메타가 남아 있음
  - `분석토큰_언론사_*.csv`
    - 실제 분석 입력본
    - 실무적으로는 "분석용 전처리 완료본"에 더 가까움

## 6. 분석 노트북별 역할

### 6-1. `01_필터감사`

- 목적
  - 최종 분석 대상 기사 확정
  - 수집 전체와 실제 분석 우주를 구분

- 입력
  - `전처리_본문_언론사_*.csv`
  - `분석토큰_언론사_*.csv`

- 수행 내용
  - 두 파일을 `article_id` 기준으로 결합
  - 날씨 기사, 클로징 기사, 중복 기사 제외 기준 적용
  - 토큰 수가 너무 적은 기사 제외
  - 스포츠/연예 등 소프트뉴스 제외
  - 미분류 기사 목록 분리
  - 각 필터 단계에서 잔존 수와 절단 수 집계

- 왜 중요한가
  - 이후 모든 분석이 이 표본 위에서 이뤄짐
  - 즉, 분석의 재현성과 타당성을 보장하는 기준 단계임
  - 여기서 확정된 최종 표본이 바로 `분석 우주`임

- 주요 산출물
  - `분석코퍼스`
  - `필터단계별잔존`
  - `필터절단수`
  - `미분류_수기코딩`

### 6-2. `02_LDA`

- 목적
  - 기사 집합에서 잠재 토픽 구조 추출
  - 적절한 토픽 수 `K` 선택

- 입력
  - `분석코퍼스`

- 수행 내용
  - `tokens` 기반 문서-단어 행렬 생성
  - `K=6~15` 범위 비교
  - coherence, held-out perplexity, seed 안정성 검토
  - 운영 가능한 토픽 수 선택
  - 문서별 토픽 비중(theta) 산출

- 왜 중요한가
  - 이후 매체그룹 비교와 감성 분석의 기준 축을 만듦
  - 토픽 해석이 흔들리면 후속 해석 전체가 흔들리므로 핵심 단계임

- 주요 산출물
  - `토픽_대표단어`
  - `문서토픽분포`
  - `K선택지표`
  - `K안정성_per_topic`

### 6-3. `03_매체그룹비교`

- 목적
  - 매체그룹별 의제 비중 차이 비교
  - 같은 의제 안에서의 표현 차이 비교

- 입력
  - `분석코퍼스`
  - `문서토픽분포`
  - `토픽_대표단어`

- 수행 내용
  - 문서별 토픽 비중(theta)을 그룹 단위로 평균
  - 그룹별 의제 비중 비교
  - 핵심 의제 선정
  - 핵심 의제 내 그룹 특화어를 `log-odds`로 계산
  - 절대표, 조건부표, 그래프 출력

- 왜 중요한가
  - 이 프로젝트의 실질적인 본 분석 단계임
  - "누가 무엇을 더 많이 다뤘는가"와 "어떤 언어적 선택을 보였는가"를 가장 직접적으로 보여줌

- 주요 산출물
  - `의제비중_절대`
  - `의제비중_조건부`
  - `의제비중_막대`
  - `핵심의제_라벨`
  - `그룹특화어_logodds`
  - `강건성_매체별특화어`

### 6-4. `04_감성`

- 목적
  - 핵심 의제 기사들의 정서값 비교
  - 매체그룹별 감성 차이 해석 보조

- 입력
  - `전처리_본문_언론사_*.csv`
  - `문서토픽분포`
  - `핵심의제_라벨`
  - `resources/knu_sentiment.json`

- 수행 내용
  - 핵심 의제 기사만 추림
  - `body_cleaned` 재형태소 분석
  - 감성사전 기반 기사별 점수 계산
  - 부정표현(`않`, `못`, `없`) 반영
  - 그룹별 평균과 coverage 계산

- 왜 중요한가
  - 의제 비중 차이와 별도로 톤 차이가 있는지 점검하는 단계임
  - 다만 현재 해석상 감성 차이의 상당 부분은 그룹 고유 논조보다 의제 구성 차이에서 발생하는 것으로 보임

- 주요 산출물
  - `감성요약`
  - `감성_문서별`
  - `감성_막대`

### 6-5. `05_워드클라우드`

- 목적
  - 그룹별 단어장을 직관적으로 보여주는 보조 시각화 생성

- 입력
  - `분석코퍼스`

- 수행 내용
  - 그룹별 토큰 빈도 집계
  - 공통 상투어 제거 버전과 원본 버전 비교
  - 워드클라우드 이미지 생성

- 왜 중요한가
  - 발표나 부록 자료로는 유용
  - 다만 본 분석의 핵심 증거로 쓰기에는 한계가 있음

- 주요 산출물
  - `워드클라우드`

  - `T2`: 문화·사회
  - `T0`: 6·3 지방선거
  - `T5`: 증시·금융

- 전체 비중
  - `T4` 약 `.20`
  - `T3` 약 `.19`
  - `T1` 약 `.18`
  - `T2` 약 `.16`

## 9. 해석상 주의할 점

- 감성 결과
  - KNU 감성사전 자체가 부정 편향을 가질 수 있음
  - 따라서 절대 수치보다 그룹 간 상대 비교와 동일 의제 내 비교가 더 중요함

- 토픽 결과

  - `T5`는 추가 민감도 확인이 필요함

  - 통신·보도는 YTN 긴 전사체 길이효과가 일부 토픽 비중에 영향을 줄 수 있음

- 워드클라우드
  - 설명용 부록으로는 유용하지만 주된 근거로 쓰기에는 적절하지 않음
  - 본증거는 `03_매체그룹비교` 산출표와 그래프에 있음
