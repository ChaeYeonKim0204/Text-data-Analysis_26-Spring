# 팀원 공유용 작업 흐름 정리

이 문서는 "이 저장소에서 지금까지 무엇을 했고, 다음에 무엇을 보면 되는지"를 빠르게 파악하기 위한 요약본입니다. 세부 규칙은 별도 문서에 있고, 여기서는 전체 흐름과 현재 상태를 중심으로 정리합니다.

## 1. 이 프로젝트가 하는 일

주제는 **2026-05-05 ~ 2026-05-11 네이버 뉴스 기사 분석**입니다.  
대상은 9개 언론사이고, 최종 비교 단위는 4개 매체그룹(경제, 통신·보도, 정치색, 지상파)입니다.

전체 흐름은 아래와 같습니다.

```text
기사 수집
-> 본문 통합
-> 전처리
-> 토큰화
-> 분석 대상 확정
-> 토픽모델링
-> 매체그룹 비교
-> 감성 분석
-> 워드클라우드
```

## 3. 분석은 어떤 순서로 진행됐는가

### 3-1. 전처리
- 기사 본문에서 기자명, 이메일, 제보문구, 방송 태그, 저작권 문구 같은 **비본문 요소**를 제거
- 원문 `body`는 보존하고, 분석용 `body_cleaned`를 별도로 생성
- 날씨 기사, 클로징 기사, 중복 가능 기사에는 삭제 대신 **플래그**를 부여

### 3-2. 토큰화
- `title_cleaned + body_cleaned`를 합친 `text`를 기준으로 Kiwi 형태소 분석 수행
- 명사류 중심으로 토큰을 추출하고, 뉴스 상투어는 불용어로 제거
- 최종 분석 입력은 `tokens` 컬럼이라고 보면 됩니다

### 3-3. 필터감사
- 전처리본과 토큰본을 합쳐서 **최종 분석 대상 기사**를 확정
- 여기서 정해진 분석 우주가 총 **10,616건**입니다

### 3-4. LDA
- 최종 분석 대상 기사로 토픽모델링 수행
- 현재 운영 결과는 **K=6 토픽**
- 각 토픽의 대표단어와 문서별 토픽 비중(theta)을 생성

### 3-5. 매체그룹 비교
- 문서별 토픽 비중을 이용해 각 매체그룹이 어떤 의제를 더 크게 다뤘는지 비교
- 같은 의제 안에서 어떤 단어를 더 많이 쓰는지도 `log-odds`로 계산

### 3-6. 감성 분석
- 핵심 의제 기사만 골라 감성사전 기반 점수 계산
- 현재 해석상 핵심은 "그룹 간 감성 차이"보다 **의제 구성 효과**가 크다는 점입니다

### 3-7. 워드클라우드
- 부록용 시각화 생성
- 본 분석의 핵심 증거라기보다 보조 설명 자료에 가깝습니다
