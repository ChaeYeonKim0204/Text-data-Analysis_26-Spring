# 검색어로 네이버 뉴스 모으기

네이버 뉴스를 **검색어로 찾아서 기사 내용을 표(CSV)로 만들어 주는** 노트북 두 개임.
"기후변화 관련 기사 일주일치를 모아 분석하고 싶다" 같은 상황에서 쓰면 됨. 코딩을 몰라도 **설정 셀의 검색어와 날짜만 바꾸면** 돌아가게 만들어 뒀음.

결과물은 이런 표임.

| link | pubdate | category | title | body | query |
|---|---|---|---|---|---|
| https://n.news.naver.com/... | 2026-05-05 07:10:00 | 사회 | 기후변화 대응 논의 | 정부가 대책을 발표했다. 전문가들은... | 기후변화 |

## 이 폴더에 있는 파일

| 파일 | 하는 일 |
|---|---|
| `검색어_뉴스_url_수집.ipynb` | 네이버 뉴스에서 검색어로 찾은 **기사 주소**를 모아 JSON으로 저장 |
| `검색어_뉴스_본문_수집.ipynb` | 그 주소로 기사를 하나씩 열어 **제목·본문·날짜·카테고리**를 CSV로 저장 |
| `README.md` | 지금 읽고 있는 안내문 |

두 노트북은 **반드시 순서대로** 실행해야 함. 1단계가 만든 주소 파일을 2단계가 읽어 쓰기 때문임.

## 전체 흐름

```
 [설정] 검색어 + 기간
        │
        ▼
 1단계  검색어_뉴스_url_수집.ipynb      크롬 창으로 검색 결과를 끝까지 스크롤
        │                              → 링크_기후변화_260505_260511.json   (기사 주소 목록)
        ▼
 2단계  검색어_뉴스_본문_수집.ipynb      주소를 하나씩 열어 기사 내용 추출
        │                              → 본문_기후변화_260505_260511.csv    (분석용 표)
        ▼
 3단계  (검색어가 여러 개일 때만)        → 통합_본문_260505_260511.csv
```

## 1단계 — 기사 주소 모으기

`검색어_뉴스_url_수집.ipynb`를 열고, **설정 셀에서 이 부분만** 고치면 됨.

```python
query_ranges = [
    {'query': '기후변화', 'start_date': '2026.05.05', 'end_date': '2026.05.11'},
]
```

- `query` — 네이버 검색창에 치는 그 검색어. 공백이나 `/`가 들어가도 됨 (`'전기차 보조금'`, `'LG U+'`)
- `start_date` / `end_date` — 기사 날짜 범위. **`YYYY.MM.DD` 형식**이고 종료일도 포함해서 모음
- 검색어를 여러 개 하려면 줄을 늘리면 됨

```python
query_ranges = [
    {'query': '기후변화',     'start_date': '2026.05.05', 'end_date': '2026.05.11'},
    {'query': '전기차 보조금', 'start_date': '2026.05.05', 'end_date': '2026.05.11'},
]
```

고쳤으면 **위에서부터 셀을 순서대로 실행**. 크롬 창이 하나 뜨고 날짜별로 검색 결과를 훑음.
화면에는 이런 식으로 진행 상황이 찍힘.

```
=== 기후변화 / 2026.05.05 ~ 2026.05.11 수집 시작 ===
새로 수집 시작
2026.05.05 — 143건 수집 / 신규 143건 추가 / 누적 143건 / 스크롤 12회 / 38.4초
다음 날짜 전 3.2초 대기
2026.05.06 — 156건 수집 / 신규 151건 추가 / 누적 294건 / 스크롤 13회 / 41.1초
...
수집 완료 — 총 981개
링크 저장: /home/me/프로젝트/data/뉴스수집/링크_기후변화_260505_260511.json
```

> 크롬 창을 마우스로 만지지 말 것. 스크롤 중에 건드리면 일부 기사를 놓칠 수 있음.
> 창이 뜨는 게 싫으면 설정에서 `HEADLESS = True`로 바꾸면 됨.

**결과**: `링크_{검색어}_{기간}.json` — 기사 주소만 들어 있는 목록.
같이 생기는 `수집로그_*.json`에는 날짜별로 몇 건 모았는지 기록돼 있음. 특정 날짜만 유독 적으면 여기서 확인하면 됨.

## 2단계 — 기사 본문 모으기

`검색어_뉴스_본문_수집.ipynb`를 열고, 설정 셀의 `query_ranges`를 **1단계와 똑같이** 맞춤. (다르면 주소 파일을 못 찾음)

그리고 실행하면 기사를 하나씩 열어 내용을 뽑음.

```
=== 기후변화 / 2026.05.05 ~ 2026.05.11 본문 수집 시작 (bs4) ===
링크 981개 불러옴: .../링크_기후변화_260505_260511.json
예상 소요 시간: 약 24분
[1 / 981] 	 0.10% 	 실패 누적: 0
[2 / 981] 	 0.20% 	 실패 누적: 0
...
중간 저장 — 100건 완료
...
실패 12건 재시도 시작...
저장 완료: .../본문_기후변화_260505_260511.csv
본문 수집 완료 — 총 979건 / 실패 2건
```

**결과**: `본문_{검색어}_{기간}.csv` — 열 구성은 아래와 같음.

| 열 이름 | 내용 |
|---|---|
| `link` | 기사 주소 |
| `pubdate` | 기사 작성 시각 (`2026-05-05 07:10:00`) |
| `category` | 네이버가 붙인 분류 (`사회`, `경제`, 스포츠 기사면 `스포츠/golf` 식) |
| `title` | 기사 제목 |
| `body` | 기사 본문 (줄바꿈은 공백 한 칸으로 정리해서 한 줄로 저장) |
| `query` | 어떤 검색어로 모은 기사인지 |

### 본문을 가져오는 두 가지 방식

| 설정 | 방식 | 속도 | 언제 쓰나 |
|---|---|---|---|
| `ENGINE = 'bs4'` (기본) | 주소만 읽어서 내용을 뽑음 | 기사당 1초 안팎 | 대부분 이걸로 충분함 |
| `ENGINE = 'selenium'` | 크롬 창으로 기사를 하나씩 열어 봄 | 기사당 2~3초 | 눈으로 확인하고 싶거나 BS4가 자꾸 실패할 때 |

기본값은 빠른 `'bs4'`이고, 여기에 `RETRY_WITH_SELENIUM = True`가 켜져 있어서 **두 번 시도해도 실패한 기사만 크롬 창으로 한 번 더** 열어 봄. 크롬이 없으면 그 단계는 알아서 건너뜀.

## 3단계(선택) — 검색어별 파일 합치기

검색어를 여러 개 돌렸다면, 본문 노트북 **맨 아래 통합 셀**을 실행하면 하나로 합쳐 줌.

- 출력: `통합_본문_{기간}.csv`
- 같은 기사가 여러 검색어에 걸린 경우 주소 기준으로 한 번만 남김
- 검색어가 하나뿐이면 안 해도 됨

## 설정값 정리

### 두 노트북 공통

| 설정 | 기본값 | 뜻 |
|---|---|---|
| `query_ranges` | 예시 1개 | 검색어와 기간. **두 노트북을 같게** 맞출 것 |
| `SPLIT_BY_MONTH` | `False` | `True`면 달마다 파일을 나눠 저장. 몇 달치를 돌릴 때 중간 재개가 편함 |
| `HEADLESS` | `False` | `False`면 크롬 창이 보임, `True`면 창 없이 실행 (코랩은 자동 `True`) |
| `SAVE_DIR_OVERRIDE` | `None` | 저장 폴더 직접 지정. `None`이면 자동 (아래 참고) |
| `MOUNT_DRIVE` | `True` | 코랩에서 드라이브에 저장할지 |
| `SKIP_COMPLETED` | `True` | 결과 파일이 이미 있는 작업은 건너뜀 |

### 주소 수집 노트북

| 설정 | 기본값 | 뜻 |
|---|---|---|
| `SORT_ORDER` | `'최신순'` | `'최신순'` / `'오래된순'` / `'정확도순'`. 하루치를 통째로 모아서 결과 자체는 같음 |
| `DAY_PAUSE_RANGE_SEC` | `(2, 5)` | 날짜 하나 끝내고 쉬는 시간(초) |
| `JOB_PAUSE_RANGE_SEC` | `(10, 25)` | 검색어 하나 끝내고 쉬는 시간(초) |
| `SCROLL_PAUSE_SEC` | `1.5` | 스크롤 한 번 내리고 기사가 뜰 때까지 기다리는 시간 |

### 본문 수집 노트북

| 설정 | 기본값 | 뜻 |
|---|---|---|
| `ENGINE` | `'bs4'` | 본문을 가져오는 방식 (`'bs4'` / `'selenium'`) |
| `RETRY_WITH_SELENIUM` | `True` | 실패한 기사만 크롬 창으로 다시 시도 |
| `CHECKPOINT_INTERVAL` | `100` | 몇 건마다 중간 저장할지 |
| `ARTICLE_PAUSE_RANGE_SEC` | `(0.4, 1.2)` | 기사 하나 끝내고 쉬는 시간(초) |
| `JOB_PAUSE_RANGE_SEC` | `(8, 20)` | 검색어 하나 끝내고 쉬는 시간(초) |
| `REQUEST_TIMEOUT_SEC` | `10` | 이 시간 동안 응답이 없으면 그 기사는 실패 처리 |

> 쉬는 시간을 0에 가깝게 줄이면 네이버가 요청을 막아 버려서 오히려 수집이 안 됨. 기본값을 그대로 두는 걸 권함.

## 결과가 저장되는 곳

`SAVE_DIR_OVERRIDE`를 비워 두면(기본값) 자동으로 정해짐.

- **로컬** — 노트북 위치에서 위로 올라가며 찾은 프로젝트 폴더 아래 `data/뉴스수집`
- **코랩** — 드라이브의 `MyDrive/data/뉴스수집` (코랩에는 프로젝트 폴더라는 게 없어서 MyDrive 기준)

드라이브에 따로 만들어 둔 프로젝트 폴더 안에 넣고 싶으면 **두 노트북 모두에** 같은 경로를 적으면 됨.

```python
SAVE_DIR_OVERRIDE = '/content/drive/MyDrive/내프로젝트/data'
```

실행하면 저장 폴더 경로가 화면에 찍히니 한 번 확인하고 넘어가면 됨.

### 만들어지는 파일들

| 파일 이름 | 무엇 |
|---|---|
| `링크_{검색어}_{기간}.json` | 1단계 결과 — 기사 주소 목록 |
| `수집로그_{검색어}_{기간}.json` | 날짜별 수집 건수·스크롤 횟수·걸린 시간 |
| `본문_{검색어}_{기간}.csv` | 2단계 결과 — 분석에 쓰는 표 |
| `통합_본문_{기간}.csv` | 3단계 결과 — 검색어별 파일을 합친 표 |
| `중간저장_*.json` | 중간에 끊겼을 때 이어서 하려고 남기는 파일 (정상 종료 시 자동 삭제) |
| `재실패_본문_*.json` | 끝까지 못 가져온 기사 주소 (사람이 직접 확인용) |
| `수집실패목록_*.json` | 작업 자체가 실패한 경우의 기록 |

기간 표시는 `YYMMDD_YYMMDD` 형식임. `260505_260511` = 2026년 5월 5일 ~ 5월 11일.
검색어에 공백이나 `/`가 있으면 파일 이름에서는 `_`로 바뀜 (`LG U+` → `LG_U+`). 원래 검색어는 CSV의 `query` 열에 그대로 남음.

## 시간이 얼마나 걸리나

대략 이 정도로 잡으면 됨 (인터넷 속도에 따라 달라짐).

- **1단계** — 하루치에 30초~2분. 기사가 많은 검색어일수록 스크롤이 길어짐
- **2단계** — 기사 1건에 약 1.3초(`bs4`) / 약 3초(`selenium`)
  - 기사 1,000건 → BS4로 약 20분, 크롬 창으로 약 50분

2단계 실행하면 시작할 때 예상 시간을 알려 주니 참고하면 됨. 오래 걸릴 것 같으면 기간을 짧게 잘라 여러 번 돌리는 게 마음 편함.

## 중간에 끊겼을 때

그냥 **노트북을 다시 실행하면 됨**. 이어서 함.

- 1단계는 **하루치**를 끝낼 때마다, 2단계는 **정해진 건수마다** 중간 저장함
- 이미 끝난 작업은 `SKIP_COMPLETED = True` 덕분에 건너뜀 → 다시 모으고 싶으면 결과 파일을 지우거나 다른 폴더를 쓰면 됨
- 정상적으로 끝나면 중간 저장 파일은 알아서 지워짐. 실패한 기사가 남았을 때만 `재실패_*.json`으로 남김

## 모은 데이터 열어 보기

**엑셀에서** — CSV를 그냥 더블클릭하면 됨. 한글이 깨지는 일이 없도록 `utf-8-sig`로 저장해 뒀음.

**파이썬에서** —

```python
import pandas as pd

df = pd.read_csv('본문_기후변화_260505_260511.csv', encoding='utf-8-sig')

print(len(df), '건')
print(df['category'].value_counts())   # 카테고리별 기사 수
print(df.head(3)[['pubdate', 'title']])
```

## 잘 안 될 때

| 증상 | 확인할 것 |
|---|---|
| 크롬 창이 안 뜨거나 실행 오류 | 크롬이 깔려 있는지 확인. WSL이면 GUI(WSLg)가 필요하고, 없으면 `HEADLESS = True`로 두면 됨 |
| `링크 파일이 없음` 오류 | 두 노트북의 `query_ranges`·`SPLIT_BY_MONTH`·저장 폴더가 같은지 확인. 1단계를 먼저 끝냈는지도 확인 |
| 날마다 0건씩 잡힘 | 네이버 검색 화면 구조가 바뀌었을 수 있음 → `HEADLESS = False`로 두고 창을 직접 보면서 결과가 뜨는지 확인 |
| 중간부터 계속 실패 | 너무 빨리 요청해서 막혔을 가능성이 큼 → 쉬는 시간을 늘리고 잠시 뒤 다시 실행 |
| 실패 기사가 좀 남음 | 본문 영역이 없는 속보·사진 기사인 경우가 많음. 전체의 1% 안쪽이면 그냥 넘어가도 됨 |
| 결과 파일을 못 찾겠음 | 실행할 때 화면에 찍힌 `저장 폴더:` 경로를 보면 됨 |
| 다시 실행했더니 `이미 완료됨, 건너뜀` | 정상임. 새로 모으려면 결과 파일을 지우거나 `SKIP_COMPLETED = False` |

## 자주 묻는 것

**Q. 검색어 여러 개를 한 번에 돌릴 수 있나요?**
네. `query_ranges`에 줄을 추가하면 순서대로 돌림. 다 끝나고 통합 셀을 돌리면 하나로 합쳐짐.

**Q. 몇 달치도 되나요?**
됩니다. 다만 기간이 길면 `SPLIT_BY_MONTH = True`로 두는 걸 권함. 달마다 파일이 나뉘어서 중간에 멈춰도 재개가 쉬움.

**Q. 특정 언론사 기사만 모을 수 있나요?**
이 노트북은 검색어 기준이라 언론사 지정은 안 됨. 다 모은 뒤 `link`의 언론사 번호(`article/023/...`)로 걸러 쓰면 됨.

**Q. 네이버에 없는 기사도 모이나요?**
아니요. 네이버 뉴스에 올라온 기사만 잡힘. 언론사 자체 사이트에만 있는 기사는 안 나옴.

**Q. 스포츠·연예 기사는요?**
페이지 구조가 달라서 따로 처리해 뒀음. `category`에 `스포츠/golf`처럼 표시됨. 빼고 싶으면 나중에 `category`로 걸러 내면 됨.

**Q. 같은 기사가 두 번 들어가진 않나요?**
날짜별·검색어별로 주소 기준 중복 제거를 하고, 통합할 때 한 번 더 함.

**Q. 이 폴더 밖에서 써도 되나요?**
네. 노트북 두 개만 복사해 가면 됨. 저장 폴더는 알아서 잡고, 원하는 위치가 있으면 `SAVE_DIR_OVERRIDE`에 적으면 됨.
